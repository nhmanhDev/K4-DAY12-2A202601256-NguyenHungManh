CP1 — 12-Factor Config, Health & Logging

⚙️ Config (pydantic-settings)

  • 7 trường đọc từ biến môi trường
  • api_token — không có mặc định → fail fast
  • @lru_cache — đọc 1 lần, cache lại
class Settings(BaseSettings): port: int = 8000 api_token: str # bắt buộc redis_url: str = "redis://localhost:6379/0" bucket_capacity: int = 10 daily_budget_usd: float = 1.0

📋 Structured Logging

  • Mỗi dòng log = 1 JSON object
  • Có event, severity, ts
  • Cloud đọc được → lọc, đếm, cảnh báo
{ "event": "chat_completed", "severity": "INFO", "ts": "2026-08-10T07:29:50...", "client_id": "sv01", "usd_cost": 0.0000226 }

CP2 — Docker Multi-stage & Bảo Mật Image

🐳 Dockerfile Multi-stage

# Stage 1: Builder FROM python:3.11-slim AS builder COPY requirements.txt . RUN pip install --prefix=/install # Stage 2: Runtime FROM python:3.11-slim AS runtime COPY --from=builder /install /usr/local COPY app ./app RUN adduser --system appuser USER appuser

✅ Các điểm quan trọng

  • Non-root user — giảm blast radius nếu bị khai thác
  • Cache layer — requirements.txt trước code → chỉ rebuild code khi sửa
  • HEALTHCHECK tích hợp trong Dockerfile
  • Image ~ 61 MB — gọn, dưới giới hạn 400MB

🔧 Docker Compose

  • 3 services: chat + redis + nginx
  • Secret dùng ${API_TOKEN} — không hardcode
  • Scale: docker compose up --scale chat=3

CP3 — API Security: Bearer Token

🔐 Xác thực theo RFC 6750

  • Header: Authorization: Bearer <token>
  • So sánh bằng secrets.compare_digest()
  • Chống timing attack — luôn chạy hết chuỗi
  • Cùng 1 thông báo lỗi cho mọi trường hợp sai

🛡️ Response 401 luôn kèm header WWW-Authenticate: Bearer — bắt buộc theo chuẩn HTTP

📝 Luồng xác thực

# 1. Thiếu header → 401 if not authorization: raise unauthorized # 2. Sai scheme → 401 scheme, _, token = authorization.partition(" ") if scheme.lower() != "bearer": raise unauthorized # 3. So sánh an toàn if not secrets.compare_digest(token, api_token): raise unauthorized # 4. Trả client_id return x_client_id or "anonymous"

CP3 — Rate Limit: Token Bucket

🪣 Thuật toán Token Bucket

  • Mỗi client có 1 xô chứa tối đa 10 token
  • Token nạp lại: 10/phút (~0.167/giây)
  • Mỗi request tiêu 1 token, hết → 429
  • Cho phép burst — im lặng thì tích, cần thì tiêu

⚠️ Luôn dùng min(capacity, tokens) — nếu không, im 1 ngày = tích 14,400 token!

💰 Cost Guard theo ngày

  • Ngân sách mặc định: $1.00/ngày
  • Mỗi request ghi chi phí bằng INCRBYFLOAT
  • Vượt budget → 402 Payment Required
  • Key Redis theo ngày UTC → tự reset sang ngày mới

So sánh: $30/tháng vs $1/ngày

Sự cố lúc 2h sáng: hạn mức tháng mất tối đa $30, hạn mức ngày chỉ mất $1 và tự hồi phục sáng hôm sau.

CP4 — Scaling & Reliability

📦 Stateless — State ở Redis

  • Lịch sử chat lưu trong Redis List
  • Giữ tối đa 12 message gần nhất (LTRIM)
  • TTL 3 ngày — tự dọn, không cần chạy cron
  • Mọi instance đọc cùng data → scale ngang an toàn

🩺 Health Probes

  • /healthz — nhẹ, không gọi Redis
  • /readyz — kiểm tra Redis, trả 503 nếu lỗi

🔄 Graceful Shutdown

  • Bắt SIGTERM + SIGINT
  • Bật cờ draining = True
  • Health check trả 503 → load balancer ngừng đẩy traffic
  • Xử lý nốt request đang chạy → thoát sạch

💡 Gọi lại handler cũ (uvicorn) sau khi bật cờ — nếu không, app bật draining rồi chạy tiếp mãi mãi.

💡 Bài Học Rút Ra

🚫 Fail Fast

Secret không có mặc định → phát hiện lỗi cấu hình ngay lúc khởi động, không phải khi bị exploit.

🛡️ Defense in Depth

3 lớp bảo vệ: Bearer token → Rate limit → Cost guard. Mỗi lớp chặn 1 loại rủi ro khác nhau.

🩺 Tách Probe

/healthz ≠ /readyz. Gộp lại → Redis lỗi 30s gây restart storm cả cụm.

📈 Stateless = Scalable

State nằm ở Redis, process không giữ gì → thêm instance bao nhiêu cũng được.

🔄 Graceful Shutdown

Bắt SIGTERM, drain request → deploy bản mới không ai thấy lỗi 502.

📋 Log cho máy đọc

JSON log 1 dòng → Cloud đọc, lọc, đếm, cảnh báo tự động. print() không làm được.
